The Story of instructions.json

How declarative AST transformation rules replaced imperative rendering loops—allowing compilers to assemble complex HTML from pure JSON instructions.

Launch V1 Instructions Studio →

Decoupling the "How" from the Code

In traditional web development, a compiler or component runner contains hundreds of lines of imperative DOM traversal code: finding containers, creating child elements, iterating arrays, and appending nodes.

When the DOM structure changes (e.g., migrating from table colgroups to CSS subgrid or wrapping cells in divs), engineers are forced to rewrite compiler source code. spec-repo solved this by inventing declarative instructions.

The 4-Part Instruction Contract

Every instruction in instructions.json declares what to do without writing a single loop:

  • destinationPath: A JSONPath expression locating where to inject nodes inside the base DOM AST (e.g. "$..*[?@.attributes['data-role'] == 'table-header-row']").
  • sourcePath: Where to read the input records from the data payload (e.g. "$.columns").
  • templateKey: The blueprint key to instantiate for each item (e.g. "buildHeader").
  • func: The operation type (e.g. "fromCollection" for array iteration, "fromObject" for single mappings).
// Anatomy of buildHeader in instructions.json:
"buildHeader": {
  "type": "single",
  "narration": "Build table header",
  "destinationPath": {
    "fileName": "base",
    "filePath": ["children"],
    "jsonPath": "$..*[?@.attributes['data-role'] == 'table-header-row']"
  },
  "sourcePath": {
    "fileName": "data",
    "jsonPath": "$.columns"
  },
  "templateKey": "buildHeader",
  "func": "fromCollection"
}

Universal Compiler Compatibility

Because instructions are pure, serializable JSON objects, any compiler—such as json-renderers-run-instructions or json-renderers-build-table—can execute them in any environment (browser, Node.js, Web Workers) with zero hardcoded assumptions.
