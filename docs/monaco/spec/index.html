The Story of spec.json

Pure, zero-dependency representations of HTML elements—decoupling tag names, CSS styling, and data interpolation tokens from JavaScript runtime frameworks.

Launch V1 Spec Studio →

What is a Tag Specification?

Before compiling an HTML element, every compiler needs to know three basic facts: What is the tag name? What attributes or CSS classes should it possess? And where does the text or child content go?

In typical component frameworks, this is written inside JSX or HTML template strings. In spec-repo, every tag is stored as a pure, serializable JSON node in spec.json.

The Tag Spec Structure

Each node in spec.json contains an immutable declarative shape:

  • tagName: Standard HTML tag ("th", "td", "tr", "button").
  • attributes: Object map of all HTML attributes, including classes, accessibility roles, and data attributes ("data-role").
  • textContent: Static text or string interpolation tokens (e.g. "${columnName}", "${serialNumber}").
  • children: Optional nested sub-tree of child tag specs.
// Example: buildHeader tag spec in spec.json:
"buildHeader": {
  "tagName": "th",
  "textContent": "${columnName}",
  "attributes": {
    "class": "py-3 px-3 fw-semibold text-uppercase small text-body-secondary border-bottom",
    "scope": "col",
    "data-column": "${columnName}"
  }
}

Theme & Framework Agnostic

Because tag specs are pure JSON, switching from Bootstrap to Tailwind CSS or adding custom dark-mode styling doesn't require modifying compiler code—simply tweak the attribute classes inside spec.json!
