The Problem with Hardcoded Component Contracts

Before definitions.json, every UI library tied component logic directly into its rendering engine. If a table needed a search toolbar, a serial number counter, or action buttons (Show, Edit, Delete), engineers had to write imperative configuration objects, event handlers, and wrapper widgets inside JavaScript frameworks.

The Declarative Definition Blueprint

In spec-repo v19, definitions.json serves as the top-level contract. It acts as an orchestra conductor, tying together three fundamental ingredients for every UI element:

  • baseFromSpec: The canonical base HTML container (e.g. "tableSimple", "formSimple").
  • instructions: The ordered list of compiler assembly rules (e.g. ["buildColgroup", "buildHeader", "buildBody"]).
  • options: Declarative feature flags such as search input wiring, serial numbering, and row option buttons.
// Anatomy of table.simple in definitions.json:
"simple": {
  "baseFromSpec": "tableSimple",
  "instructions": [
    "buildColgroup",
    "buildHeader",
    "buildBody"
  ],
  "options": {
    "search": {
      "initialize": "searchFrame",
      "showLabel": "searchLabel",
      "showInput": "searchInput"
    },
    "serial": {
      "initialize": "serialRoot",
      "showSerial": "serialChild"
    }
  }
}
