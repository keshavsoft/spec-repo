Repository Usage & How It Works

An end-to-end breakdown of how specifications, instructions, and compiler engines collaborate to generate native DOM elements.

1. Installation

Install spec-repo via npm or your preferred package manager:

npm install spec-repo

2. Module Imports

By default, spec-repo exports the latest canonical version (v17), along with all tag blueprints, instructions, and definitions:

// Default export gives the full specification catalog
import spec from "spec-repo";

// Named exports provide modular access
import { 
  spec,          // Full specification tree (table, select, forms, datalist)
  tags,          // Raw HTML tag blueprints
  tagsSchema,    // JSON schema validation rules
  instructions,  // JSONPath assembly directives
  definitions    // High-level component recipes
} from "spec-repo";

console.log(spec.buildHeader);
// Outputs: { tagName: "th", textContent: "${columnName}", attributes: { ... } }

Importing Specific Versions

If your application targets a specific version, you can import directly from sub-paths:

// Version 17 (Current)
import specV17 from "spec-repo/src/v17/spec.json" with { type: "json" };

// Version 2 (Legacy Tag-Only)
import specV2 from "spec-repo/archive/v2/spec.json" with { type: "json" };

3. How It Works: The 4-Stage Assembly Pipeline

The compiler does not generate HTML imperatively. Instead, it follows a deterministic 4-stage pipeline orchestrated by definitions.json and instructions.json:

1️⃣
Load Base AST
The definition selects an initial skeleton AST from spec.json (e.g., tableSimple with <table>, <thead>, <tbody>).
2️⃣
Resolve Instruction
The compiler looks up the instruction by key (e.g. buildHeader), reading its source data path and destination target path.
3️⃣
JSONPath Query & Target
Locates target injection points dynamically in the base AST using data roles, such as $..*[?@.attributes['data-role'] == 'table-header-row'].
4️⃣
Hydrate & Inject
Clones the template tag, substitutes token variables (${columnName}, ${rowValue}), and attaches them into the destination.

4. Instruction Anatomy Explained

Here is what an instruction looks like under the hood (from src/v17/instructions.json):

{
  "buildHeader": {
    "type": "single",
    "narration": "Build table header",
    "destinationPath": {
      "fileName": "base",
      "filePath": ["children"],
      "jsonPath": "$..*[?@.attributes['data-role'] == 'table-header-row']"
    },
    "sourcePath": {
      "fileName": "data",
      "jsonPath": "$.columns"
    },
    "templateKey": "buildHeader",
    "func": "fromCollection"
  }
}
Property Type Description
type string Execution mode: single (1-to-1 or list-to-container), rowOnColumn (matrix 2D table body), or columnOnRow (nested dropdowns/datalists).
destinationPath.jsonPath string JSONPath expression matching target nodes in the base template where newly created nodes must be appended or unshifted.
sourcePath.jsonPath string JSONPath expression querying the incoming user data (e.g., column array or row data array).
templateKey string | object The key in spec.json / tags.json used as the template blueprint.
func string Transformation strategy (e.g. fromCollection to iterate and clone for every data item).

5. Parameter Naming Standard (KeshavSoft Convention)

All controller functions and compilers consuming spec-repo adhere strictly to the KeshavSoft single-object argument pattern:

  • Single Config Object: All functions receive one destructured parameter object.
  • in Prefix: Incoming parameters are prefixed with in (e.g. inSpec, inData, inConfig).
  • local Prefix: Variables inside the function body are assigned to local-prefixed identifiers before execution.
function compileComponent({ inSpec, inData, inRecipe }) {
  // 1. Map inputs to local variables
  const localSpec = inSpec;
  const localData = inData;
  const localRecipe = inRecipe;

  // 2. Perform compiler logic strictly using local variables
  const baseAst = JSON.parse(JSON.stringify(localSpec[localRecipe.baseFromSpec]));
  // ... execute instructions
  return baseAst;
}

6. Global Registration

In browser environments or micro-frontends without bundlers, importing src/v17/index.js automatically registers the specification catalog onto the window global object under window.specRepo:

// Available in browser console or legacy scripts:
console.log(window.specRepo.spec);
console.log(window.specRepo.definitions);
console.log(window.specRepo.instructions);
